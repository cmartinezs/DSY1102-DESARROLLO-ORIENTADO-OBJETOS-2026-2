2 · Estructura base

No crees un repositorio nuevo por ejercicio. Todo el semestre vive dentro del mismo repo.

DSY1102-012V-nombre-apellido/
├── README.md
├── .gitignore
├── practica/
├── examples/
├── labs/
├── proyecto-formativo/
├── desafios/
└── evaluaciones/
    ├── ep1/
    ├── ep2/
    ├── ep3/
    └── eft/

Usa un solo proyecto Java y un package distinto por ejercicio. Para el usuario c.martinez:

practica/semana-02/fundamentos-java/
└── src/
    └── cl/duoc/cmartinez/practica/semana02/
        ├── ejercicio01/Main.java
        ├── ejercicio02/Main.java
        └── ejercicio03/Main.java
package cl.duoc.cmartinez.practica.semana02.ejercicio01;

public class Main {
    public static void main(String[] args) {
        // solución del ejercicio
    }
}

labs/semana-02/cuenta-simple/
├── README.md
└── src/
    └── cl/duoc/cmartinez/labs/cuentasimple/
        ├── Main.java
        └── Cuenta.java
package cl.duoc.cmartinez.labs.cuentasimple;

PetCare se mantiene en una sola carpeta durante el semestre:

proyecto-formativo/
└── petcare/

Package base sugerido para el ejemplo:

cl.duoc.cmartinez.petcare
No crear petcare-final, petcare-v2, petcare-ahora-si. Git ya mantiene el historial.

desafios/desafio-150-java/
└── src/
    └── cl/duoc/cmartinez/desafios/d150/
        ├── ejercicio001/Main.java
        ├── ejercicio002/Main.java
        └── ...

Ejemplo:

package cl.duoc.cmartinez.desafios.d150.ejercicio025;

evaluaciones/
├── ep1/
├── ep2/
├── ep3/
└── eft/

Ejemplo de package:

cl.duoc.cmartinez.evaluaciones.ep1

Estas carpetas son exclusivas para entregas evaluadas y deben contener exactamente lo necesario para ejecutar y revisar la entrega.

Reglas:

  • usa el usuario institucional, no el correo completo;
  • elimina los puntos;
  • usa minúsculas;
  • no agregues sigla ni sección;
  • no inventes abreviaciones diferentes.
Correcto
c.martinez → cmartinez → cl.duoc.cmartinez
a.perez → aperez → cl.duoc.aperez
Incorrecto
cl.duoc.c.martinez
cl.duoc.carlosmartinez
cl.duoc.dsy1102.s012v

  • No ejecutar git init dentro de cada proyecto.
  • No guardar ZIP del mismo proyecto dentro del repo.
  • No subir `.idea`, compilados, logs o secretos.
  • No escribir packages con el usuario Duoc sin normalizar.
