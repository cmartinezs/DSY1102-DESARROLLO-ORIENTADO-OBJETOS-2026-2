DSY1102 · Repositorio del estudianteCurso
ESTÁNDAR OBLIGATORIO · DSY1102-012V

Un repositorio para toda la asignatura, ordenado desde el primer día.

Esta guía explica cómo nombrar el repo, dónde guardar cada tipo de trabajo, qué archivos subir, qué ignorar y cómo entregar sin perderse entre carpetas.

Nombre del repositorio

Formato:

<SIGLA>-<SECCION>-nombre-apellido

Para esta asignatura:

DSY1102-012V-carlos-martinez
Regla: sigla y sección exactas; nombre y apellido en minúsculas; palabras separadas por guion; sin espacios, tildes ni caracteres especiales.

Estructura base

No crees un repositorio nuevo por ejercicio. Todo el semestre vive dentro del mismo repo.

Cuando varios ejercicios solo requieren un Main.java, usa un solo proyecto Java y un package distinto por ejercicio. No crees un proyecto IntelliJ completo por cada uno.

practica/semana-02/fundamentos-java/
└── src/
    └── cl/duoc/dsy1102/s012v/practica/semana02/
        ├── ejercicio01/Main.java
        ├── ejercicio02/Main.java
        ├── ejercicio03/Main.java
        └── ejercicio04/Main.java
package cl.duoc.dsy1102.s012v.practica.semana02.ejercicio01;

public class Main {
    public static void main(String[] args) {
        // solución del ejercicio
    }
}

Un laboratorio tiene su propia subcarpeta. Dentro van todos los archivos necesarios para ejecutar esa actividad.

labs/semana-02/cuenta-simple/
├── README.md
└── src/
    └── cl/duoc/dsy1102/s012v/labs/cuentasimple/
        ├── Main.java
        └── Cuenta.java

Si más adelante usamos Maven o Gradle, también se incluye el archivo de construcción correspondiente.

PetCare, JavaFX, aplicaciones con BD y evaluaciones de tipo proyecto se suben como proyecto completo dentro de una subcarpeta.

Sí subir
  • src/
  • recursos necesarios
  • README.md
  • pom.xml / build.gradle cuando corresponda
  • configuración de aplicación necesaria y sin secretos
No subir
  • .idea/, .vscode/, *.iml
  • out/, target/, build/, .gradle/
  • *.class, logs y temporales
  • tokens, passwords, claves o credenciales

Para los 150 ejercicios pre-POO se usa un solo proyecto y un package por ejercicio:

desafios/desafio-150-java/
└── src/
    └── cl/duoc/dsy1102/s012v/desafios/d150/
        ├── ejercicio001/Main.java
        ├── ejercicio002/Main.java
        ├── ejercicio003/Main.java
        └── ...

En desafíos posteriores de POO, JavaFX o BD, cada desafío que ya sea una aplicación completa podrá tener su propia subcarpeta de proyecto.

evaluaciones/
├── ep1/
├── ep2/
├── ep3/
└── eft/

Estas carpetas son exclusivas para entregas evaluadas. La entrega debe contener exactamente lo necesario para ejecutar y revisar esa evaluación.

  1. Ejecuta y prueba la entrega.
  2. Revisa git status.
  3. Haz un commit final identificable.
  4. Haz git push.
  5. Entra a github.com y verifica que los archivos realmente estén allí.
  6. Entrega la URL indicada por el docente.

Base sugerida:

cl.duoc.dsy1102.s012v

Ejemplos válidos:

cl.duoc.dsy1102.s012v.practica.semana02.ejercicio01

El package y la carpeta física deben coincidir. En packages no se usan guiones, espacios, mayúsculas, tildes ni caracteres especiales.

Usa commits pequeños y comprensibles:

practica: resolver ejercicio 03 semana 02
lab: implementar validación de retiro
petcare: agregar clase Mascota
challenge: resolver ejercicio 018
evaluacion: entregar EP1

Si trabajas en el instituto y luego en casa:

git pull
# trabajar y probar
git status
git add .
git commit -m "mensaje claro"
git push
En el otro computador: primero git pull, después modifica archivos.

  • No crear un repo por ejercicio.
  • No guardar ZIP del mismo proyecto dentro del repo.
  • No crear petcare-final, petcare-final2, petcare-ahora-si: Git ya guarda versiones.
  • No ejecutar git init dentro de cada proyecto; debe existir un solo .git, el del repositorio de la asignatura.
  • No subir configuraciones locales del IDE, binarios ni secretos.
Importante: si el docente no puede encontrar, clonar y ejecutar una entrega de manera razonable, la estructura del repositorio todavía no está terminada.

Checklist antes de decir “listo”

☐ Nombre correcto del repositorio
☐ Archivo en la carpeta correcta
☐ Package coincide con la carpeta
☐ Código compila y ejecuta
☐ Sin `.idea`, `out`, `target`, logs o `.class`
☐ Sin credenciales
☐ Commit realizado
☐ Push realizado y verificado en GitHub
