# Errores frecuentes al comenzar POO

## 1. “POO = usar Java”

No. Java permite programar orientado a objetos, pero escribir Java no garantiza un diseño orientado a objetos.

## 2. “Objeto = cosa física”

No. Un objeto puede representar conceptos intangibles como una reserva, una venta o una autorización.

## 3. “Una clase es solo un grupo de variables”

Una clase modela un concepto y también puede definir comportamientos y reglas relacionadas con ese concepto.

## 4. “Todo debe convertirse inmediatamente en una clase”

No. La POO no consiste en crear clases por obligación. Primero debemos identificar conceptos y responsabilidades útiles.

## 5. “La programación estructurada deja de servir”

No. Dentro de los métodos seguiremos utilizando `if`, ciclos, variables y algoritmos.

## 6. “Más clases significa mejor diseño”

No necesariamente. Muchas clases sin responsabilidades claras pueden hacer el sistema más difícil de comprender.

## 7. “Primero escribo código y después veo qué objetos aparecen”

Puede funcionar en ejercicios muy pequeños, pero al aprender POO conviene practicar también el camino inverso:

```text
problema
→ conceptos
→ responsabilidades
→ relaciones
→ código
```

## Señal de comprensión

Si puedes explicar por qué una responsabilidad pertenece a un objeto y no a otro, estás comenzando a razonar más allá de la sintaxis.
